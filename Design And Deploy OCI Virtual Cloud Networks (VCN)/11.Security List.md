### **Introduction to Security Lists**

*   Hello and welcome to this new lesson on the OCI VCN security list. My name is Sergio Castro with Oracle University. And let's go ahead and get started.
*   A security list is a set of common firewall rules associated with a subnet.
*   Every single resource that you have on that subnet is bound by these rules.
*   When you create a security list, you can decide if the rules are going to be **stateful** or **stateless**.

### **How Security Lists Work: A Visual Example**

*   Visually, a security list is applied to a subnet or a set of subnets on a VCN.
*   **Example Scenario:**
    *   A VCN with CIDR block 10.0.0.0/16.
    *   Three subnets, all bound by one security list.
    *   The security list has two rules:
        *   **Ingress Rule:** Allow port 80 (HTTP) for traffic coming in.
        *   **Egress Rule:** Allow port 1521 (Database) for traffic going out.

#### **Understanding the Port 80 (Ingress) Rule**

*   If a rule is **stateful**, you only have to define it once, and the permission is allowed for both the incoming (ingress) and the returning (egress) traffic.
*   Assume we have a web server in one of the subnets. Every resource in all three subnets has port 80 enabled because of this rule.
*   The source `0.0.0.0/0` (quad zero) means "from anywhere," including the internet, a home office, a cafeteria, or even from within the VCN itself. The subnet `10.0.1.0/24` also falls under this "anywhere" definition.

#### **Understanding the Port 1521 (Egress) Rule**

*   The egress rule is more restrictive. It allows resources in the subnet to send data out to a specific destination, in this case, the `10.0.2.0/24` network on port 1521.

#### **Key Principle: Default Deny**

*   Every rule in the security list applies to every node (resource) in the subnet.
*   If a permission is not explicitly defined in a rule, it is **denied by default**.
*   In our example, there is no rule for port 22 (SSH). Therefore, you **cannot SSH into any of these instances**.

### **Enforcement and Configuration of Security Lists**

*   Security list rules are enforced at the **Virtual Network Interface Card (vNIC)** level.
*   When a vNIC is added to a compute instance in a subnet, the rules of that subnet's security list are applied to it.
*   The rules define what traffic is allowed in (ingress) and out (egress) of the subnet.
*   When creating a subnet, you must specify its security list(s). If none is specified, it uses the **default VCN security list**.
*   You can change the security list for a subnet after creation.
*   A single subnet can have up to **five security lists** associated with it.

#### **Scope of Enforcement**

*   These rules apply to any instance in the subnet, whether it is:
    *   Communicating with another instance within the same VCN.
    *   Communicating with a host outside the VCN (in another VCN or outside OCI entirely).
*   When communicating with a host outside your VCN, your traffic is bound by your VCN's security rules *and* the rules on the destination host's network.

### **Stateful vs. Stateless Rules**

#### **Stateful Rules (Default)**

*   Uses **connection tracking**.
*   You only need to specify the rule in one direction (e.g., ingress). The return traffic for that connection is automatically allowed.
*   **Example:** If you create a stateful ingress rule allowing port 80, you do **not** need to create a corresponding egress rule for the return traffic.

#### **Stateless Rules**

*   You **must specify both the ingress and egress rules** for a connection.
*   This allows for very detailed and granular control over traffic flow.
*   **Example for Port 80 (HTTP):**
    *   **Ingress Rule:**
        *   Source: `0.0.0.0/0`
        *   IP Protocol: TCP
        *   Source Port: (Ephemeral - any port on the client)
        *   Destination Port: 80
    *   **Egress Rule:**
        *   Destination: `0.0.0.0/0`
        *   IP Protocol: TCP
        *   Source Port: 80 (from the server)
        *   Destination Port: (Ephemeral - back to the client's port)

### **Important Considerations and Best Practices**

*   By default, every security rule you create is **stateful**. You must manually change it to stateless if needed.
*   **ICMP Protocol:** For ICMP (used for ping, etc.), you often need to specify matching ingress and egress rules **regardless** of whether you are using stateful or stateless rules.
*   **IPv6 Rules:**
    *   IPv4 rules do **not** automatically apply to IPv6 traffic.
    *   You must create separate, specific rules for IPv6.
    *   The notation for "anywhere" in IPv6 is `::/0`, not `0.0.0.0/0`.
    *   Pay close attention to the protocol and port configurations for IPv6, as they can differ from IPv4.
