### **Part 1: Default Security List Rules**

*   Whenever you launch a VCN, either by the wizard or create it manually, you will always get a security list with three default rules in it.
*   They are **stateful rules**:
    *   One for **SSH (port 22)**
    *   Two for **ICMP** (but not for echo)
*   The ICMP rules do not include **type 8 (echo)**. Therefore, if you try to ping a compute instance, it will not reply.

### **Part 2: Testing Connectivity and Adding an ICMP Echo Rule**

#### **Initial Ping Test (Fails)**
*   I have three instances: a web server, a Windows Server, and a standard compute instance.
*   Trying to ping the compute instance fails because the echo rule is missing.

#### **Adding the ICMP Echo Rule**
*   To enable ping, I add a new **stateful** ingress rule to the security list.
    *   Source: `0.0.0.0/0` (anywhere)
    *   Protocol: ICMP
    *   Type: 8 (Echo)
*   After adding the rule, the ping is successful.

#### **Testing Ingress vs. Egress**
*   **Removing the Echo Rule:** After removing the rule, pinging *into* the instance fails again.
*   **Testing Egress from the Instance:** I SSH into the compute instance (port 22 is allowed by the default rule). From inside, I can successfully ping an external address (`1.1.1.1`).
    *   **Reason:** The default security list has an **egress rule allowing "All Protocols"**. This allows the instance to send traffic out, including ping requests.
*   **Removing the "All Protocols" Egress Rule:** After removing this rule, the instance can no longer ping the external address, proving that egress rules control outbound traffic.

### **Part 3: Stateful vs. Stateless Rule Behavior**

#### **Changing SSH Rule to Stateless (Breaks Connection)**
*   I change the SSH rule from **stateful** to **stateless**.
*   **Result:** I can no longer SSH into the compute instance.
*   **Reason:** A stateless rule requires a matching egress rule for the return traffic. Without it, the response from the instance is blocked.

#### **Fixing SSH with Stateless Rules**
*   To make SSH work with a stateless rule, I must add a corresponding **egress rule**:
    *   Protocol: TCP
    *   Source Port: 22
    *   Destination: `0.0.0.0/0`
    *   Destination Port: (Ephemeral - the client's port)
*   After adding this matching egress rule, SSH works again.

#### **Creating a Specific ICMP Rule**
*   Instead of allowing `0.0.0.0/0`, I create a more secure ICMP rule using my workstation's specific IP address (`/32`).
*   This allows only my machine to ping the instance, demonstrating granular control.

### **Part 4: Configuring Access for Specific Services**

#### **Enabling Web Access (Port 80)**
*   I add a **stateful** ingress rule for port 80 (HTTP) with source `0.0.0.0/0`.
*   After adding the rule, I can successfully access the pre-configured Apache web server from my browser.

#### **Enabling Windows RDP Access (Port 3389)**
*   I add a **stateful** ingress rule for port 3389 (RDP) with source `0.0.0.0/0`.
*   After adding the rule, I can successfully establish a Remote Desktop connection to the Windows Server.

### **Part 5: IPv6 Configuration**

*   My Windows Server has an IPv6 address, but I cannot access it via the web browser.
*   **Reason:** Security lists and route tables are separate for IPv4 and IPv6. The existing IPv4 rules do not apply to IPv6 traffic.
*   **Solution:** I must add a new **IPv6 ingress rule** for port 80 and a corresponding **IPv6 route rule** pointing to the internet gateway.
*   After adding the IPv6-specific rules, I can access the web server using its IPv6 address.

### **Part 6: Rule Precedence - Stateless vs. Stateful**

*   **Scenario:** I investigate what happens if the same rule exists as both stateful and stateless.
*   I have a **stateful** SSH rule that works.
*   I then add an identical **stateless** SSH rule but do *not* create the required matching egress rule.
*   **Result:** SSH access fails.
*   **Conclusion:** When a rule is duplicated, the **stateless rule takes precedence** over the stateful rule, even if the stateless rule is incomplete and blocks the connection.
