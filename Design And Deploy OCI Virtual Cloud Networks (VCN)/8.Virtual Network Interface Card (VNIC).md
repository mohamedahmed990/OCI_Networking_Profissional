*   A VNIC enables the instance that you create (a compute or a database node) to connect to the VCN or to the subnet in that VCN.
*   It determines how the instance connects with other instances or endpoints inside the VCN or even outside the VCN.

### **Core Components of a VNIC**

Each VNIC resides on a subnet and a VCN and has the following components:

*   **Primary Private IP Address:**
    *   You can have one primary IP address from the subnet to where that VNIC resides.
    *   It is chosen by Oracle randomly from the IP addresses of your CIDR block, or you can go ahead and make a selection. Reserve-- specify what IP address from that range you want to use.
    *   Remember that we're talking about the private IP address.

*   **Secondary Private IP Addresses:**
    *   You can have up to 32 IP addresses secondary.
    *   That means that that's the primary address that we're talking about in the previous point, and then you can have up to 32 optional secondary private IPv4 addresses.
    *   That's a lot. It depends on your design, but you can have that and you can leverage that. And you don't have to use them all. You can use one or two if you want.
    *   From the same subnet in which the VNIC is chosen by you, the addresses are chosen by you or by Oracle.

*   **Secondary IPv6 Addresses:**
    *   You can have up to 32 optional secondary IPv6 addresses.
    *   Of course, you need to enable the VCN and the subnet with an IPv6 prefix.
    *   This is available for all commercial and government OCI realms.

*   **Public IPv4 Address:**
    *   An optional public IPv4 address for each private IP that you have.
    *   Remember that when you create a subnet, a public subnet, it will have a private IP address, and it's optional for you to enable this with public IP.
    *   The public IP is going to be from the pool of addresses from OCI or you can bring your own IP.

*   **DNS Name:**
    *   An optional DNS name for each private IP address. Let's say my IP one, my IP two, or my private IP one, my private IP two. You can select that.

*   **MAC Address and VLAN Tag:**
    *   It comes with a Mac address.
    *   Also a VLAN (virtual local area network) tag assigned to your instance. This is relevant for bare metal instances.

*   **Source/Destination Check Flag:**
    *   You can have a flag-- it comes with a flag that you have the option of enabling.
    *   This flag is for checking the source and destination.
    *   Normally, this is relevant when you're using this as your an IP as a routing mechanism.

*   **Network Security Group (NSG):**
    *   Your VNIC can be enabled to be managed or constrained by a network security group.

*   **Friendly Name and OCID:**
    *   Each VNIC has a friendly name that you can assign.
    *   It will always have an OCID. Every single resource that you create an OCID-- an OCI comes with an OCID and OCID is the Oracle Cloud ID identifier.

### **Multiple VNICs and Network Architecture**

*   You can have multiple VNICs on virtual machines. It doesn't mean that you only have one VNIC.
*   **Example Configurations:**
    *   **VM1:** Has a single VNIC connected to subnet A.
    *   **VM2:** Has two VNICs associated with that compute instance; one going to subnet A and another one going to subnet B.
    *   **VM3:** Is connecting to subnet B of VCN1 and connecting to subnet X on VCN2.
*   When a secondary VNIC is added, a new ethernet device is added and recognized by that instance operating system.
*   This depends on your architecture and how you design your network.

### **Working with Secondary Private IPs**

*   You can have secondary IPs on your VNICs. That means that you can enable the IP addresses that you have on your VNICs to have a second one.
*   Each VNIC can have additional IPs called secondary private IPs, maximum of 31 in addition to the one that you created, so that makes 32.
*   The secondary private IP is assigned only after the instance is launched on the secondary VNIC.
*   There's a two-step process:
    1.  You need to enable this.
    2.  You need to update the instance operating system to use the secondary IP address. It doesn't come by default.
*   You can move a secondary private IP from one VNIC to another or from a VNIC on one instance to a VNIC on another instance.

### **Public IP Addresses: Ephemeral vs. Reserved**

*   A private IP address instance that you create always has a private IP address. By default, we're talking about the primary IP address.
*   When a public subnet is used, a private IP address can have an optional public IP assigned to it. It is optional.
*   If you decide to have a public instance on a public subnet without a public IP, then it's not reachable over the open internet. This applies to your secondary VNIC as well.
*   You can assign a given resource multiple public IPs across one or more VNICs.
*   For the public IP to be reachable over the internet, you must have:
    *   An internet gateway.
    *   A route rule that will take you to the internet.
    *   Security rules, either on a security list or on a network security group, that will allow the service.
*   **Ephemeral Public IPs:** Assigned by Oracle randomly.
*   **Reserved Public IPs:** You can reserve a public IP address first, then it can be unassigned, and then you can assign it to a resource later. It is persistent and lives beyond the life of your resource.
*   There is no charge for public IP addresses even if they're unassigned.
