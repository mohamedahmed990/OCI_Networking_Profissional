### **1. Overview of Public IP Addresses**

*   A public IP address is an IPv4 address that is reachable from the open internet.
*   Any object in your tenancy that needs to be directly reachable from the internet, or that needs to reach the internet, must have a public IP address.
*   Depending on the resource type, there might be other requirements. For example:
    *   A **compute instance** needs more than just a public IP; it also requires an internet gateway, route rules, and security permissions.
    *   A **NAT gateway** or a **public load balancer** comes with a public IP address, which is all it needs.
*   The public IP address is an object with its own OCID (Oracle Cloud Identifier).
*   The networking service defines the public IP object, which consists of:
    *   The IPv4 address (the four octets).
    *   Properties that define its behavior (e.g., whether it is reserved or ephemeral, its placement, and related resources).

### **2. Types of Public IP Addresses**

*   **Ephemeral Public IP Addresses:**
    *   Assigned by Oracle to your resource automatically when you define it (e.g., a compute instance).
    *   Temporary in nature; the address returns to the Oracle pool when you delete the resource.
    *   You cannot change an ephemeral IP to a reserved one after creation.

*   **Reserved Public IP Addresses:**
    *   Lives beyond the life cycle of the resource it is assigned to.
    *   If you delete a virtual machine with a reserved public IP, the address returns to your reserved status and can be reused on another resource.
    *   You can move a reserved public IP from one vNIC to another.

### **3. Public IPs and Virtual Network Interface Cards (vNICs)**

*   A vNIC comes with a primary private IP address and can have a primary public IP address mapped to it.
*   You can assign secondary private IPs and secondary public IPs to a vNIC.
*   You can have multiple public IPs across one or more vNICs assigned to a single resource.
*   A single compute instance can have up to 30 public IP addresses.

#### **Requirements for Internet Connectivity**

*   Having a public IP address is not enough for a compute instance to reach the internet.
*   The instance must also be:
    *   On a **public subnet**.
    *   Have an **internet gateway** configured as the next hop in a **route table**.
    *   Have permissions assigned via a **security list** or **network security group (NSG)**.

#### **Key Points on Assignment**

*   When you launch an instance in a public subnet, it gets a public IP by default, but this is **optional**.
*   You can decide a compute instance on a public subnet should **not** have a public IP.
*   Without a public IP, even with an internet gateway and correct routing, the instance cannot be reached from the open internet, nor can it reach out directly.
*   An instance without a public IP can still leverage a **NAT gateway** for outbound connections.

### **4. Bring Your Own IP (BYOIP)**

*   You can bring your own IPv4 or IPv6 address prefixes to Oracle Cloud Infrastructure.

#### **Requirements for BYOIP:**

*   **Ownership:** You must have ownership of the CIDR block and prove it to Oracle for validation.
*   **Regional Internet Registries:** Supported RIRs include ARIN (North America), RIPE NCC (Europe), and APNIC (Asia-Pacific).
*   **Clean History:** The addresses must have a clean history (e.g., not associated with spam).
*   **Limits and Quotas:**
    *   Addresses can only be imported to a **specific region**.
    *   The minimum IPv4 block size is **/24**. The maximum is **/8**.
    *   The IPv6 prefix must be a **/48**.
    *   You cannot bring the same range to more than one compartment at a time.
    *   You can bring up to **20** IPv4 CIDR blocks or IPv6 prefixes in combination.

### **5. IP Pools**

*   If you bring your own IP, you can create **IP Pools** to organize and distribute them within OCI.
*   When launching a resource, you can choose to get the public IP from your own pool instead of the Oracle-provided pool.
*   Public CIDR blocks assigned to a pool are available **only to your tenancy**, not to child tenancies. A different tenancy must import its own block.
*   These pools are available for all resources that require a public IP address.
*   You can add more CIDR blocks to a pool at any time or delete them.
*   You can create a **reserved IP address** from your own pool, which behaves the same as a reserved address from Oracle's pool.

#### **Public IP Pool Details:**

*   To use your public IP pools, you must first import your addresses.
*   To reserve an Oracle-supplied public IP address, select the **Oracle public pool** when creating the reserved public IP.
*   You can create up to **10** public IP pools in any given compartment.
*   A public pool can have **zero or more** IP CIDR blocks.
*   The minimum pool size is **/28**, and the maximum is **/24**.

### **Additional Information**

*   The IP address ranges that Oracle uses are publicly available and can be retrieved for your use, including programmatically with infrastructure as code.
