### **Core OCI Infrastructure Concepts**

#### **1. Regions**
*   A region is a location in the world where Oracle Cloud Infrastructure has presence. Basically, we have data centers there.
*   So that's a region where Oracle Cloud Infrastructure has data centers in it.
*   A region has one or more availability domains.

#### **2. Availability Domains (ADs)**
*   The availability domain is one or more data centers.
*   Each availability domain can be composed of one or more data centers that are close together physically that act as one availability domain.
*   If we have more than one availability domain, then they're separate enough to be able to keep the resources running. If catastrophe hits one of the availability domains, then we have two more to rely on them.
*   This is basically for high availability and disaster recovery.
*   We have several regions with three availability domains. We have many regions with one availability domain.

#### **3. Fault Domains (FDs)**
*   Each availability domain comes with three fault domains.
*   A fault domain is one rack that has many resources, compute resources, networking resources, load balancing resources all in one rack.
*   This will allow redundancy within the availability domain. So if one fault domain goes down, we still have two more fault domains to rely upon.
*   Every single availability domain has three fault domains, each one of the availability domains.
*   Even those that we have three availability domains per region, each one of them have three fault domains. So if we have three availability domains, that means that we have nine fault domains.

### **Virtual Cloud Network (VCN) Overview**

*   The Virtual Cloud Network is the representation of a physical data center.
*   Basically, it's the resource that you need for other resources to be mounted on. You need networking, especially if you're going to have multi-tier architectures.
*   A Virtual Cloud Network resides in a single region. If you need a Virtual Cloud Network in another region, then you need to create that other VCN in that other region.

---

### **VCN Components and Architecture**

Here is a deeper look at a Virtual Cloud Network with its related resources.

#### **Subnets**
*   This Virtual Cloud network comes with two subnets, one of which is public and the other one is private.
*   This looks to be a multi-tier application where the public has a compute instance, the public subnet and the private subnet has a database.

#### **Gateways**
Gateways allow communication with resources outside of the Virtual Cloud Network.

*   **Internet Gateway:**
    *   Will allow communication from your resources in a public subnet to the open internet.
*   **NAT Gateway:**
    *   Will allow resources in a private subnet to communicate with resources in the open internet.
    *   Traffic is going to be generated from within the VCN out to the open internet. But there's no initiation from the open internet to resources in your private subnet.
*   **Service Gateway:**
    *   Bypasses the internet so basically allows your resources to remain within OCI when communicating with the Oracle Services Network.
    *   The Oracle Services Network is an Oracle network that contains resources that are publicly available. And it's an OCI construct. So it's better to bypass the internet and keep traffic from within OCI.
*   **Dynamic Routing Gateway (DRG):**
    *   Will allow you to communicate with on-premises resources through either a virtual private network, VPN, a site-to-site VPN, or through a digital circuit via FastConnect.
    *   The dynamic routing gateway can be leveraged for other utilizations like connecting to other virtual cloud networks in another region.

#### **IP Address Management**
*   The Virtual Cloud Network has a CIDR block, an IPv4 CIDR block for it, for example, 10.0.0.0/16.
*   You can have up to five non-overlapping IPv4 CIDR blocks, non-overlapping on the VCN.
*   We do allow the CIDR block to be modified once you create that. For example, you can decrease the size of the block (e.g., from /16 to /17) provided that you don't have resources from the portion that you're reducing.
*   IPv6 is optional upon creation or later on. You can enable IPv6 on your Virtual Cloud Network.
*   The fact that you enable IPv6 on the VCN does not automatically assigns IPv6 CIDR blocks to the subnets. You need to enable the subnets as well.
