### **Purpose and Function of an Internet Gateway**

*   The internet gateway allows resources on a **public subnet** to communicate with the **open internet**.
*   It is an **optional** component. You can have a public subnet without an internet gateway.
*   Without an internet gateway and the correct route rules, a public subnet will **not be reachable** from the open internet.
*   It supports two types of connections:
    *   **Egress:** Connections initiated from within the VCN to the internet.
    *   **Ingress:** Connections initiated from the open internet into the VCN.

### **Requirements for Using an Internet Gateway**

For a resource to use the internet gateway, the following components must be in place:

*   **Public Subnet:** The resource must reside in a subnet configured as public.
*   **Public IP Address:** The resource itself must be assigned a public IP address.
*   **Internet Gateway:** The gateway must be created in the VCN.
*   **Route Rule:** The route table associated with the public subnet must have a rule with:
    *   **Destination:** `0.0.0.0/0` (the entire internet)
    *   **Target:** The Internet Gateway
*   **Security Rules:** The security list or network security group must have rules that **permit** the specific traffic (e.g., port 80 for web traffic, port 22 for SSH).

### **Key Characteristics and Restrictions**

*   **One per VCN:** You can have **only one internet gateway** per Virtual Cloud Network.
*   **No Transitive Routing:** Only resources **within the VCN** can use the internet gateway. It does not support transitive routing. For example, an on-premises resource connected to the VCN cannot use this gateway to reach the internet.
*   **Route Table is Mandatory:** After creating an internet gateway, you **must add a route rule** to the public subnet's route table for traffic to flow.
*   **Security Zones:** You cannot add or move an internet gateway if your VCN is part of a **security zone**, which restricts modifications.

### **Summary of Components in a Working Setup**

A fully configured setup for internet access includes:

*   A resource (e.g., a web server) in a **public subnet** with a **public IP address**.
*   An **internet gateway** attached to the VCN.
*   A **route table** for the public subnet with a rule sending `0.0.0.0/0` traffic to the internet gateway.
*   A **security list** or **network security group** with rules allowing the desired traffic (e.g., port 80 ingress for web access).
