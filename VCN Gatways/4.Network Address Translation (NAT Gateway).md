### **Introduction to the NAT Gateway**

*   Hello, my name is Sergio Castro at Oracle University. And welcome to this lesson. Today we're seeing the NAT gateway, the network address translation gateway.
*   The NAT gateway is used when you want resources on a **private subnet** in your Virtual Cloud Network (VCN) to initiate communication **out to the open internet**.

### **Purpose and Use Cases**

*   It allows resources in a private subnet to initiate outbound traffic to the internet. Examples include:
    *   A database node that needs to download a patch, update, or upgrade.
    *   Any private resource that needs to access external services.
*   It can also be used for resources on a **public subnet that do not have a public IP address** assigned to them.
*   Hosts can initiate outbound connections to the internet and receive responses.
*   **A key restriction:** Traffic **cannot be initiated from the internet** into the private resources via the NAT gateway. It is for outbound traffic only.

### **Key Characteristics and Benefits**

*   **No Internet Gateway Required:** A unique feature of OCI is that you **do not need an Internet Gateway** to use a NAT Gateway. The NAT Gateway provides direct outbound internet access.
*   **High Availability:** NAT gateways are highly available.
*   **Supported Protocols:** Supports TCP, UDP, and ICMP (ping) traffic.
*   **Public IP for Private Resources:** It gives an entire private subnet access to the internet without assigning a public IP address to each individual resource.

### **Configuration and Limits**

*   **Default Limit:** You are typically allowed **one NAT gateway per VCN** by default.
*   **Increasing Limits:** You can request a service limit increase if you need more than one NAT gateway.
*   **Concurrent Connections:** A single NAT gateway supports up to **20,000 concurrent connections**.
*   **IP Addresses:** Resources using the NAT gateway can have either ephemeral or reserved private IP addresses.

### **Routing and Scope**

*   **Route Table Requirement:** For the NAT gateway to work, you must add a **route rule** in the private subnet's route table with:
    *   **Destination:** `0.0.0.0/0` (the internet)
    *   **Target:** The NAT Gateway
*   **No Transitive Routing:** The NAT gateway can **only be used by resources within its own VCN**.
    *   It does **not** support transitive routing. This means:
    *   Resources in a peered VCN **cannot** use this NAT gateway.
    *   On-premises resources connected via FastConnect **cannot** use this NAT gateway.

### **Visual Example**

*   In a typical configuration, the NAT gateway is shown with an arrow pointing **from the private subnet out to the internet**, illustrating the one-way, initiated traffic flow.
*   This contrasts with an Internet Gateway, which is often depicted with bidirectional arrows, showing it can handle both inbound and outbound initiated traffic.
