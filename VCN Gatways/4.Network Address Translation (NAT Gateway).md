
### **Introduction to the NAT Gateway**

*   Hello, my name is Sergio Castro from Oracle University, and welcome to this lesson on the NAT Gateway (Network Address Translation Gateway).

### **Purpose and Core Function**

*   The NAT gateway is used to allow resources in a **private subnet** within your Virtual Cloud Network (VCN) to initiate outbound connections to the **open internet**.
*   **Use Case Examples:**
    *   A database node that needs to download a patch, update, or version upgrade from the internet.
*   It also provides internet access for resources in a **public subnet** that do not have a public IP address assigned to them.
*   The key principle is that hosts can initiate outbound connections to the internet and receive responses, but **inbound traffic cannot be initiated from the internet** to the private resources through the NAT gateway.

### **Key Features and Characteristics**

*   **High Availability:** NAT gateways are designed to be highly available.
*   **Protocol Support:** It supports TCP, UDP, and ICMP ping traffic (useful for troubleshooting).
*   **Connection Limits:** A single NAT gateway supports up to **20,000 concurrent connections**.
*   **IP Address Support:** It can be used with resources that have either ephemeral (temporary) or reserved IP addresses.

### **A Key Distinction of OCI's NAT Gateway**

*   In Oracle Cloud Infrastructure (OCI), the NAT gateway **does not require an Internet Gateway** to function.
*   This is a unique feature of OCI. In other cloud providers, a NAT gateway typically needs to communicate with an Internet Gateway to reach the public internet.
*   In OCI, the NAT gateway is the only resource you need for outbound internet connectivity from a private subnet.

### **Configuration and Limitations**

*   **Route Requirement:** For the NAT gateway to work, you must add a route in your route table that directs outbound internet traffic to the NAT gateway as the next hop.
*   **Quantity per VCN:**
    *   The default service limit is **one NAT gateway per VCN**.
    *   While you can request a service limit increase for more, it is rare to need a second one due to the high connection limit.
    *   If you have more than one, you must specify which NAT gateway your resources will use.
*   **Scope and "No Transitive Routing" Rule:**
    *   The NAT gateway can **only be used by resources within its own VCN**.
    *   It **cannot be used for transitive routing**. This means:
        *   Resources in a VCN connected via Remote Peering Connection **cannot** use this VCN's NAT gateway to reach the internet.
        *   Resources in an on-premises network connected via FastConnect **cannot** use this VCN's NAT gateway to reach the internet.
    *   Those external resources would need their own NAT gateway in their own VCN.

### **Visual Configuration Summary**

*   In a network diagram, the NAT gateway is depicted with arrows showing traffic flowing **outbound** from the private subnet to the internet.
*   This contrasts with an Internet Gateway, which is shown with bidirectional arrows, indicating it can handle both outbound and inbound traffic initiation.
