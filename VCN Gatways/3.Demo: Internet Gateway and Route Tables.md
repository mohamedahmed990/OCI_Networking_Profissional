### **Introduction to the Demo**

*   Hello, and welcome to another demonstration, a very fun demonstration. This is the internet gateway and route tables.
*   Because we need to demonstrate the internet gateway, we'll use a compute instance to go out of our Virtual Cloud Network and to the open internet. So let's go ahead and get started.

### **Step 1: Navigating to the VCN and Preparing the Internet Gateway**

*   I'm going to access my console, and I'm back into the general view. And the very first thing that we need to do is go into the Virtual Cloud Networks.
*   Remember that we have two of them, the wizard VCN and the manual VCN.
*   Because we're adding an internet gateway, let's go ahead and use our manual VCN, which comes with no internet gateway.
*   I'm going to delete the previously created "demo" internet gateway. And we're going to add a new one, and we're going to call this **my internet gateway**.

### **Step 2: Creating the Internet Gateway**

*   It's really easy to create an internet gateway. You just click on **Internet Gateway** under Resources once you're in your VCN and click the **Create Internet Gateway** button.
*   Give it a name. We mentioned that we're going to call this **MyIG** for Internet Gateway.
*   Select the right compartment, which is the certification compartment.
*   As easy as that, we created an internet gateway.

### **Step 3: Creating a Route Rule to the Internet**

*   We must add a route rule in the route table to leverage this internet gateway.
*   Under Resources, click **Route Tables**. You can either create a new route table or use the default one. In this case, I'm using my **default route table**. You cannot delete this route table ever.
*   Click **Add Route Rules**.
*   **Configure the Rule:**
    *   We're using **IPv4**.
    *   The **target type** is **internet gateway**.
    *   The **destination CIDR block** is `0.0.0.0/0` (the quad zero, meaning the entire open internet).
    *   The **next hop** or target is the **MyIG** internet gateway.
    *   I can add a description, like "to the internet".
*   Click to add the route rule.

### **Step 4: Testing Connectivity via SSH and Ping**

*   We will use a compute instance created in a previous demo to test the connection.
*   To connect, we need the SSH key that was downloaded previously. I will use **Cloud Shell**.
*   I open the folder with the key, copy it, and create a new file in Cloud Shell called `MyKey` to paste the private key into.
*   I change the file permissions: `chmod 400 MyKey`.
*   I retrieve the **public IP address** of my compute instance from the console.
*   Now I can SSH into the instance using the command: `ssh -i MyKey opc@<instance_public_ip>`
*   Once connected, I test outbound connectivity by pinging a public DNS server: `ping 1.1.1.1`
*   The ping is **successful**, proving the internet gateway and route rule are working.

### **Step 5: Demonstrating the Impact of Route Rules**

*   To demonstrate how route rules control access, I will change the rule to be more restrictive.
*   I go back to the default route table and **edit** the rule we just created.
*   I change the **destination CIDR block** from `0.0.0.0/0` to `8.8.8.8/32` (only the Google DNS server).
*   After saving this change, the route table now **only allows traffic to 8.8.8.8**.
*   **Result:** The Cloud Shell session to the compute instance is **broken** because Cloud Shell's IP address is not `8.8.8.8`. This proves the rules take effect immediately and precisely control traffic flow.

### **Step 6: Restoring Full Access**

*   I edit the route rule again and change the destination back to `0.0.0.0/0`.
*   After saving, full internet access is restored.
*   I open a new Cloud Shell session, SSH back into the compute instance, and confirm I can once again ping `1.1.1.1`.

### **Conclusion**

*   This completes this demonstration of the internet gateway and the route rules. Thank you for watching.
